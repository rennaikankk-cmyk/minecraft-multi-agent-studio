# 全角色战术参考清单 · M2/M3 实现输入

> **本文件是"打法/机制描述"，不是代码。** 依据 AGENTS.md §0.6：只描述开源实现（Meteor Client、Baritone、mineflayer-pvp 等）验证过的**机制与参数**，以及本项目自定的作战战术，供在确定性 TypeScript 反射层**自研重写**。**严禁**将任何 GPL 源码逐行翻译或复制进本项目。本文所述均为公开可观察的游戏机制与通用算法思路（idea），不含受版权保护的具体实现。
>
> **覆盖范围**：§0~§8 为战斗反射与侦察战术（战斗类落 **M3 战斗反射**，前提是先实测 Mineflayer 无头达 <50ms 时序，见 §0）；§9~§12 为其余作战角色（突袭/防御/建造与生产/后勤）战术，多数落 **M2/M4**，不依赖战斗时序达标，可并行推进。§13 为**共享世界记忆的服务器隔离**——横切所有角色的硬规则（每服独立世界，记忆按 serverProfileId 硬隔离）。§14 为**现成 Mineflayer 插件对照表**——哪些 MIT 插件可直接依赖、哪些 GPL 只可参考、哪些必须自研。防御（§10）与建造与生产（§11）刻意针对侦察（§8）的地狱门扫描做**对称反制**。共六类角色（侦察/突袭/防御/战斗/建造与生产/后勤）——建造与生产由建造+农场合并，因食物自动化后不是瓶颈，真正瓶颈是装备/附魔/黑曜石/水晶/附魔瓶等消耗性战备物资。

## 0. 时序预算（决定一切的前提）

| 环节 | 目标 | 说明 |
|---|---|---|
| 事件循环单帧抖动 | < 50ms | 超过则战斗必输；这是 M3 的达标线，也是是否需要 Rust/换栈的唯一判据 |
| 图腾补位（totem re-equip） | 下一 tick（≤50ms） | 图腾被消耗后必须在同帧或下一帧补回副手，否则连击致死 |
| 水晶检测→反应 | ≤1 tick | 看见敌方放水晶到自己反应的窗口 |
| Minecraft 一个 tick | 50ms | 服务器逻辑帧；所有"tick 级"指标都以此为基准 |

**先测量再优化**：M3 第一步不是写战斗逻辑，是写一个能持续采样事件循环延迟的探针，在多 bot、寻路、扫描同时跑的负载下观察 p99 抖动。达标才继续；不达标先定位阻塞源（多半是寻路或区块解析占用主线程）。

## 1. AutoTotem（图腾自动管理）—— 最高优先级反射

**机制**：不死图腾（totem of undying）握在副手（off-hand）时，致命伤会消耗图腾免死。战斗中图腾被消耗后，必须立刻从背包补一个回副手。

**要搬的打法**：
- **触发时机**：监听副手槽变化 / 生命值骤降事件，图腾一旦离开副手 → 下一 tick 立即补位。不要轮询，用事件驱动。
- **优先级**：补图腾的优先级高于**一切**其他动作（攻击、移动、放水晶都要让路）。这是反射层里的最高抢占项。
- **失败降级**：背包无图腾 → 立即触发撤退/断线反射（进入 L0 存活逻辑），不要继续战斗。
- **健康阈值**：可在生命值低于某阈值（如 ≤ 半血）时预防性确认副手有图腾。

**本项目对应**：反射层最高抢占项，技能 `manage.totem`。与 L0 存活逻辑联动。

## 2. CrystalAura（水晶 PvP）—— 核心输出机制

**机制**：末影水晶（end crystal）放在黑曜石/基岩上，被攻击时爆炸，对范围内实体造成大量伤害。攻防两端都靠它。

**要搬的打法（放置点评分）**：
给候选放置位打分，选最优点放置并立即引爆。评分维度：
- **对敌伤害**：候选点爆炸对目标造成的预估伤害（距离越近越高，但受方块遮挡衰减）。
- **对己伤害**：同一次爆炸对自己的预估伤害（必须低于某安全阈值，否则自爆）。
- **可达性**：该点是否有合法承载方块（黑曜石/基岩）、是否被其他方块阻挡放置。
- **净收益** = 对敌伤害 − 对己伤害 × 自保权重。取净收益最高且对己伤害 < 阈值的点。

**引爆时机**：放置后同 tick 或下一 tick 引爆（攻击水晶实体）。延迟越大越容易被敌方先炸。

**自保红线**：任何预估自伤会击穿"当前生命 − 图腾余量"的放置一律否决——宁可不打这一下，也不能自杀。

**本项目对应**：技能 `combat.crystal`。放置点评分是纯几何+伤害公式计算，天然适合确定性代码。**这是最吃时序的模块，M3 的时序测试要以它为主要负载。**

## 3. AutoArmor（护甲自动换装）

**机制**：护甲耐久耗尽会碎；战斗中要把破损护甲换成背包里完好的备件。

**要搬的打法**：
- **耐久阈值**：某件护甲耐久低于阈值（如剩余 < 10% 或绝对值 < N）时，从背包换上同部位完好护甲。
- **换装时机**：避开正在承受连击的瞬间换（换装有短暂空档）；优先在拉开距离/无水晶威胁的间隙换。
- **优先级**：低于 AutoTotem，高于主动进攻。

**本项目对应**：战斗时序换甲技能 `manage.armor`（M3，<50ms 反射级，避连击空档换装，须待 §0 时序探针通过后自研）。与已落地的 `inventory.equip-armor@1.0.0`（M2、非战斗、"每槽选最优"日常换甲）是**两个不同技能**：后者管"平时穿最好的"，前者管"打架中耐久崩了瞬间补"。

## 4. Surround / 自我保护落块

**机制**：在自己脚下四周（有时含脚下）快速放黑曜石/末地烛，阻止敌方贴脸放水晶、限制敌方近战走位。

**要搬的打法**：
- **落块顺序**：先落四个水平相邻方块（N/E/S/W），封住贴脸水晶位；黑曜石优先（抗爆）。
- **触发**：检测到敌方逼近水晶放置距离时触发；解除战斗后回收/离开。
- **与移动的冲突**：surround 会限制自身移动，需与撤退逻辑协调——撤退优先级更高。

**本项目对应**：可作为 `combat.crystal` 的防御子模式或独立技能。

## 5. KillAura / 近战锁定（谨慎）

**机制**：自动瞄准并攻击范围内目标。

**要搬的打法**：
- **目标选择走确定性敌我识别**（白名单外即敌，见 AGENTS.md §0.1），**不经 AI**。
- **攻击间隔**：遵守武器冷却（attack cooldown），满冷却才挥砍，否则伤害衰减。
- **朝向**：瞄准要"够用即可"，过度精确的瞬间转头是明显 bot 破绽（见 §7 反检测）。

**本项目对应**：技能 `combat.melee`。**注意**：近战 aura 是反作弊最敏感的行为之一，优先级低于水晶战术，且要配合反检测节流。

## 6. 寻路与移动（Baritone 打法参考）

**机制**：Baritone 是业界最强的 Minecraft 寻路实现（A* + 大量实战启发）。

**要搬的打法（思路，不搬代码）**：
- **公路循迹**：无规则服的坐标轴高速/地狱顶层公路是笔直隧道，循迹可用简单的"沿轴对齐 + 前方障碍检测"，不需要完整 A*。
- **鞘翅飞行力学**：起飞、烟花助推节奏、落地缓冲——纯物理，确定性实现。
- **基岩顶巡逻**（本项目侦察角色核心）：能上基岩顶时移动最省事（平坦无阻挡）。见 §8。

**边界**：远距离探索寻路是 CPU 密集，若实测阻塞事件循环（>50ms），才考虑抽独立 Rust 寻路服务（AGENTS.md §0.5）。**先测量。**

## 7. 反检测 / 类人化（诚实边界）

**目标**：降低明显的 bot 破绽，**不等于免疫封号**（AGENTS.md §0.4）。

**要搬的打法**：
- 转头/瞄准加入微小噪声与转速上限，避免瞬间 180°。
- 动作之间加入人类量级的随机延迟抖动，避免固定周期。
- 避免亚 tick 完美连招（完美到不可能是人的操作 = 明显信号）。

**红线**：这些只降低破绽，残余封号风险由使用者承担；不得在文档/代码里把"反封号"写成已解决。

## 8. 基岩顶巡逻 + 地狱门扫描（本项目侦察角色专属战术）

> 这是用户提出、本项目侦察角色的核心侦察手段，不是通用外挂功能。

**原理**：
1. **基岩顶可达性**：部分无规则服未修补下界基岩顶（Y=127 之上）通道，bot 可上到基岩顶。顶上平坦、无怪物、鞘翅移动效率全游戏最高。
2. **区块数据可扫描**：服务器向客户端同步的区块数据包含**脚下整个区块柱**的方块信息。bot 站在基岩顶即可读取顶层以下的方块，**无需下到下界内部**即可扫描已加载区块中的地狱门方块。
3. **已激活门 = 基地嫌疑**：已激活的地狱门（含紫色传送门方块）意味着有人使用过。**下界坐标 ×8 = 主世界对应坐标**，是主世界基地的高概率嫌疑点。

**打法流程**：
- **入服先探测**：尝试上基岩顶。成功 → 启用本战术；失败（服务器已修补）→ **自动去除此项**，退回地狱顶层公路巡逻，不做无谓尝试。探测结果记入 **ServerProfile**，换服重新探测。
- **巡逻扫描**：在基岩顶沿网格/螺旋巡逻，对每个新加载区块扫描地狱门方块（传送门方块 nether_portal / 黑曜石框架）。
- **标记而非核实**：扫描 bot **只负责标记**——把门的下界坐标、激活状态、发现时间**写入共享世界记忆**（pgvector，P2.1）。**每条标记必须携带 `serverProfileId` + 维度 + 坐标**，缺一拒绝写入——每个服务器是独立世界，A 服的门在 B 服毫无意义，绝不允许跨服混记（详见"共享世界记忆的服务器隔离"节）。
- **分工核实**：由**战略层**读取标记，按优先级（活跃度、聚集度）指派**其他侦察 bot** 前往主世界对应坐标（×8）核实是否有基地。上层标记、下层核实，是集群协作的典型样例。

**确定性 vs AI 切分**：
- 确定性：基岩顶可达性探测、区块地狱门扫描、坐标 ×8 换算、标记写入。
- AI（战略层）：已标记门的核实优先级排序、是否值得投入 bot 核实。

**本项目对应**：技能 `probe.roof`（可达性探测）、`scan.portal`（区块地狱门扫描）、`log.coordinate`（标记写入）。

## 9. 突袭 Raider —— 攻破基地

**目标**：以最低资源代价打穿基地外壳、翻走高价值物资、全身而退。

**要搬的打法**：
- **破墙优先级**：黑曜石抗爆极高，硬用 TNT 费料——首选**末影水晶贴墙连爆**（对方块破坏效率高于 TNT），附魔镐补挖，凋灵拆大面积墙。评估目标外壳材质后选最省料的方式。
- **接近路线**：不走正门。从远处斜向下挖，或经**下界对应点（×8）**贴近再上主世界，减少被防御 bot 边界扫描发现。
- **择时**：优先在目标**无人在线 / 防御 bot 撤离**时突入（侦察角色提供的玩家活动规律是关键输入）。
- **翻箱优先级**：潜影盒 > 末影箱线索 > 附魔台/信标等高价值方块 > 普通资源。背包满优先打包潜影盒带走。
- **脱离**：预置**珍珠停滞**（ender pearl stasis）或竖井下潜逃生路线；达撤退阈值（生命、来敌数）立即断线保号。**突袭 bot 死亡 = 损失一整套突入装备，撤离优先于贪财。**

**确定性 vs AI**：确定性=敌我识别、破墙机制、翻箱优先级、撤退触发；AI=突入方式选择、何时放弃。

**本项目对应**：`mine.obsidian` · `place.crystal` · `ignite.tnt` · `spawn.wither` · `loot.chest` · `breach.wall`。依赖侦察坐标、农场原料、战斗护航。

## 10. 防御 Defender —— 守基地（对称反侦察）

**核心认知**：敌人会用**我们侦察角色同一套手段**（基岩顶地狱门扫描、公路跟踪）找我们，所以防御从"不被发现"开始。

**要搬的打法**：
- **反坐标暴露**：己方基地**不用主世界地狱门**，或用完即拆/远置，避免暴露 ×8 坐标（这正是 §8 扫描战术的反制）。核心仓与门厅分离。
- **分层预警**：外环（区块加载边缘检测新实体）→ 中环（边界巡逻发现玩家）→ 内环（触墙/破坏方块）逐级升级报警。
- **迟滞而非死守**：单个防御 bot 打不过突袭队，价值在**拖延 + 报警 + 疏散**——封门（黑曜石/岩浆幕）、水阻爬墙，拖到战斗 bot 回援或核心物资撤离完成。
- **反跟踪**：发现被玩家尾随时不直接回基地，绕路/断线甩开，**绝不把敌人带回家**。
- **失陷协议**：达失陷阈值触发 `COMPROMISED`——核心物资撤离、≥10000 格外重建，撤离优先于反击。

**确定性 vs AI**：确定性=敌我识别、入侵探测、报警派发、巡逻路径、反跟踪甩尾；AI=迎战/躲藏/撤离、是否触发失陷协议。

**本项目对应**：`patrol.perimeter` · `detect.intruder` · `alert.swarm` · `seal.entrance`。

## 11. 建造与生产 Infrastructure —— 隐蔽 + 战争经济引擎

**为什么合并（建造 + 农场）**：自动化农场是**建造的产物**，建好即自运转，不是需要持续操作的独立角色。而且**食物不是瓶颈**——金萝卜/金苹果农场一旦建成产量绝对够吃，fire-and-forget。真正需要盯产量的是**消耗性战备物资**：装备、附魔、黑曜石、末影水晶、附魔瓶（经验瓶）。本角色 = 建隐蔽基地 + 搭建并运转这些战备物资生产线。

**核心认知**：无规则服第一防御是**没人找得到**（第二才是墙厚）；没有稳定的战备物资生产，突袭和战斗就是无源之水。

**要搬的打法（建造/隐蔽）**：
- **选址硬规则（确定性可校验）**：远离坐标轴与主干道 N 格以上、远离主世界地狱门连线、**避开整数/对称/整千坐标**（人类爱建在整千坐标，避开反而隐蔽）。可编码的布尔校验，不靠 AI 直觉。
- **伪装与埋深**：外壳埋地下/山体，入口伪装（假墙、无关方块群）。
- **抗爆结构**：核心库用**黑曜石壳 + 隔空层**抵御水晶连爆；关键箱藏多层无关空间、不集中堆放（一次被翻不全损）。
- **分散建点**：生产/仓储/休整分点建、坐标各自独立，高特征建筑（刷怪塔）远离核心；任一点暴露不牵连其他。
- **己方标记**：所有隐蔽点坐标写入共享世界记忆并标"己方隐蔽点"，**防止己方侦察 bot 把自家门误标为嫌疑基地**。

**要搬的打法（生产/经济）**：
- **按战争节奏调产**：要突袭 → 火药/水晶原料/末影珍珠/TNT 拉满；防御期 → 图腾材料/黑曜石/附魔瓶优先。
- **库存水位线**：每种战备物资设**低/目标/上限**三档。低于低水位报警并顶格生产，到上限转产其他，避免单一囤积。确定性计数逻辑。
- **食物免管理**：食物线建好即忽略，不设水位、不占调度注意力。
- **抗突袭**：生产点与核心仓**分离且不放全部产出**——成品定期由后勤转运隐蔽仓，现场只留在制品；即使某生产点被端，战争储备不清零。

**基地自举顺序（从 0 到量产水晶的科技树）**：水晶不能凭空造——末影水晶 = 7 玻璃 + 1 末影之眼 + 1 恶魂之泪,每一样都要有前置产线。一座"完整基地"= 走完这条依赖链。建造角色按此**固定顺序**逐层解锁,每层是下一层的前置:

1. **生存底座（裸装冷启动，先活下来再谈建造）**：假设 bot 空手落在出生点——无规则服的出生点是**永久战区**（岩浆/黑曜石陷阱、出生点守尸党、满地griefer、夜晚怪物），一落地就开建 = 送死。这一层是一套**确定性冷启动生存协议**，跑完才允许进第 2 层：
   - **出生点即战区，第一动作是脱离**：绝不在出生点半径内停留或建造。落地先判周边即时威胁（岩浆/掉落/玩家），沿最短安全方向离开出生辐射区。有下界高速则优先走高速远行数千格到低流量区再落脚（复用 `travel.highway`）；无则地表/地下远离。
   - **裸装自保工具链（固定合成顺序）**：撸木 → 木镐/木剑 → 挖石 → 石镐/石剑/石斧。目标是尽快有近战武器和能挖石的镐,别在木器阶段恋战。
   - **掘洞自保**：天黑或遇敌无法脱离时,就地掘洞钻入、身后封块（"掘地三尺"）,避免露天过夜。**禁止直下**（防岩浆/摔落——确定性硬规则）。
   - **不饿死**：路上打动物/摘浆果拿到基础食物顶过冷启动期,不追求营养最优,只求血条不因饥饿见底。
   - **遇玩家走确定性交战逻辑**：白名单外即敌,但裸装期**默认脱离/藏匿**（打不过）,只有确定性存活逻辑判定能赢才交战——冷启动期几乎永远选逃。
   - **存活阈值（确定性）**：血量低于阈值 → 撤退/进食/掘洞;夜晚或光照不足 → 就地掩蔽;背包无武器 → 优先补工具而非赶路。
   - **落脚点判据**：远离出生点辐射区 + 低玩家流量 + 有木/石/水/动物 → 才算"底座就绪",可开建临时庇护所与第一个基础食物农场（胡萝卜/土豆）,进第 2 层。
   - **确定性 vs AI**：确定性=撸木/合成链、掘洞自保、直下禁令、血量/食物/光照阈值、遇敌脱离;AI=往哪个方向逃、逃多远、哪里算安全落脚点、何时判定"可以开建了"。
   - **复用 L0 存活状态机（不重写）**：饥饿/岩浆/坠落/溺水/卡死的阈值检测与进食/撤退/上浮动作,P1.1 L0 安全层已有确定性实现;冷启动生存**在其之上**补一层行为编排（脱离出生战区、合成工具链、掘洞、遇敌藏匿）,不得另写一套存活逻辑——两者是同一层能力,归 M1。
   - 目标：脱离出生战区、有石器与近战武器、不饿死、有安全落脚点——**能过夜、能挖矿、没被守尸党秒**,才谈得上建造。
2. **材料层**：刷石机（圆石无限）→ 熔炉阵、脚手架、活塞原料；**刷铁机**（铁傀儡塔）→ 铁 = 甲/砧/漏斗/矿车/水桶；树场（木/木炭）。目标：有铁有石有漏斗，能造自动化设施本体。
3. **玻璃层**：**刷沙机**（TNT 复制推落沙——2b2t 系无规则服经典 duper）或沙漠采集 → 熔炉阵烧 → 玻璃。玻璃是水晶外壳（7/个）的大头，产量要顶格。
4. **下界层**：下界基地 + 通道；**烈焰人场**（要塞刷怪 → 烈焰棒 → 烈焰粉）；**恶魂场**（玄武岩三角洲/专用平台 → 恶魂之泪,水晶必需且最卡产量）；顺带金块场（金苹果/交易）。
5. **末影层**：**末影人场**（下界洞穴顶/末地 → 末影珍珠）。末影珍珠 + 烈焰粉 → **末影之眼**。
6. **黑曜石层**：黑曜石生成器（水+熔岩定向铺 → 挖）→ 放水晶的底座、重生锚、基地墙、抗爆壳。
7. **附魔层**：经验场（刷怪/末影人）+ 甘蔗→书架 + 青金石 → 附魔台;砧组合附魔;**附魔瓶**（经验瓶）由经验场灌装。产出成套附魔装备。
8. **量产水晶（终点）**：玻璃 + 末影之眼 + 恶魂之泪 → 末影水晶流水线。走到这里 = 一座**完整基地**,可持续量产水晶/装备/附魔/黑曜石,喂养突袭与战斗。

> **难度与分期**：第 3~5 层的刷沙机/恶魂场/末影人场多是复杂红石/活塞结构,Mineflayer 无头 bot 逐块按 schematic 铺设**慢且脆**,属**后期能力**（M4 之后）。MVP 阶段先做能跑的简单农场（胡萝卜、刷石、铁傀儡塔）+ 半自动搬运,复杂 duper 类留到蓝图执行器与建造精度硬化后。**不要在文档里把"全自动量产水晶"当成近期可交付**——它是终局,不是起点。

**存储系统（不只是堆箱子）**：作战集群吞吐大、损耗快,仓储要能**自动分拣 + 自动打包 + 水位可读**,否则后勤和生产互相堵。设计要点:
- **漏斗分拣系统**：物品经漏斗滤器按类入位（甲/水晶/火药/建材各自成区）,生产线产出直接进对应仓,不靠人/bot 手动归类。
- **潜影盒装载**：整组物资自动灌入潜影盒,后勤 `pack.shulker` 领走即走,减少满箱 bot 往返（往返=暴露）。
- **溢出与水位**：每种战备物资仓接**计数器 → 低/目标/上限三档水位**,低于低水位触发生产报警,到上限溢出转存/停产,水位数据写入共享世界记忆供战略层调度。
- **分散不集中**（复用抗突袭原则）：核心隐蔽仓 + 前线周转仓 + 应急暗仓,3-2-1 存放,任一仓被端不清零;高价值（附魔装/水晶）优先进最深隐蔽仓。
- **确定性**：分拣路由、装箱、水位计数与报警全是确定性逻辑;AI 只决定"仓建在哪、水位阈值定多少"。

**确定性 vs AI**：确定性=选址硬规则校验、方块摆放/蓝图执行、自举顺序推进、农场循环、收割补种、分拣路由、库存水位计数与报警；AI=选址/布局/建什么、走到自举第几层、战备物资优先级与水位阈值。

**本项目对应**：`build.blueprint` · `place.blocks` · `build.wall` · `build.hidden-base` · `farm.crop` · `farm.mob` · `generate.obsidian` · `smelt` · `craft.item` · `enchant.gear` · `store.sort` · `pack.shulker`（自举顺序 = 战略层按科技树逐层下发的建造目标序列,非单个技能）。

## 12. 后勤 Logistics —— 让损失可补充

**核心认知**：作战集群"死一个 bot 掉一套装"是常态，后勤把损失变成可快速补充，把前线和仓储解耦。

**要搬的打法**：
- **预置补货套件**：按角色打包标准潜影盒（突袭套=镐/水晶/TNT/珍珠/图腾；战斗套=甲/水晶/图腾/金苹果；侦察套=鞘翅/烟花/食物）。bot 死后重生领套即可再上线，无需临时凑装。
- **隐蔽转运**：运输是暴露风险最高的环节（满箱 bot 是活靶）——路线避开公路热点、分批小额运、必要时经下界短途；贵重整合进潜影盒减少往返。
- **分散储备（3-2-1 思路）**：核心隐蔽仓 + 前线周转仓 + 应急暗仓，任一仓被端不全损。每仓库存与坐标写入共享世界记忆（仅集群可读）。
- **前线解耦**：前线 bot 只管打，补给由后勤推送到就近周转仓，前线不回后方，降低暴露主基地风险。

**确定性 vs AI**：确定性=打包/分类/补货/转运执行；AI=补货优先级、转运时机与路线取舍。

**本项目对应**：`store.stash` · `pack.shulker` · `resupply` · `sort.items`。

## 13. 共享世界记忆的服务器隔离（横切所有角色的硬规则）

**核心认知**：每个 Minecraft 服务器是**完全独立的世界**。同样的坐标 (100, 64, -200) 在 A 服是敌方基地、在 B 服可能是岩浆海。集群一旦跨服混用记忆，轻则浪费 bot 跑空路，重则把己方隐蔽点误判成敌情、按错误坐标发动突袭。这是多服运营下最容易出、也最难排查的一类错误，必须在数据层根除，不能靠 bot"记得住"。

**硬规则（确定性，写入 P2.1 记忆层设计）**：

- **写入门槛**：任何位置类记忆（地狱门标记、基地嫌疑点、己方隐蔽点、仓库坐标、公路节点、库存水位）必须携带完整三元组 **`serverProfileId` + 维度 + 坐标**。缺任何一项 → 拒绝写入（fail-closed），不做默认值兜底。
- **查询隔离**：一切记忆查询**强制**按当前连接的 `serverProfileId` 过滤——这个过滤加在仓储层（repository 层 SQL WHERE 子句），不靠调用方自觉传参。调用方无法发起不带服务器过滤的位置查询。
- **换服即换记忆空间**：Bot 断开 A 服连接 B 服的瞬间，其可见的世界记忆整体切换；上一个服的坐标、路径、目标一律失效，进行中的坐标类任务作废重排。ServerProfile 探测类结果（基岩顶可达性、版本、防作弊表现）同理各服独立。
- **嵌入检索同样隔离**：pgvector 相似度检索必须先按 `serverProfileId` 过滤再算相似度，防止语义检索绕过 SQL 过滤把别服的"相似基地"混进结果。
- **跨服分析是显式特权**：只有战略层可以发起跨服对比查询（如"哪个服的经济好打"），且结果只能用于选服决策，**不得**把其中任何坐标直接下发为另一个服上的行动任务。
- **非位置记忆也标来源**：战斗经验、玩家行为画像等看似"可通用"的记忆同样标注来源服——同一玩家 ID 在不同服可能是不同人，防作弊差异也让战斗参数不可平移。

**确定性 vs AI**：隔离本身 100% 确定性（schema 必填字段 + 仓储层强制过滤），AI 无权豁免；AI 只在显式跨服分析查询里读聚合结果。

**本项目对应**：P2.1 长期记忆 schema 必含 `serverProfileId`（NOT NULL + 外键）；所有 `log.coordinate` / `scan.portal` 写入路径必传；查询 API 以当前 ServerProfile 为隐式强制参数。

## 14. 现成 Mineflayer 插件对照表（能直接用什么、只能参考什么）

**核心结论**：Mineflayer 生态有大量现成插件，**MIT 许可的可以直接依赖**（像已锁定的 pathfinder 一样走供应链流程），**GPL-3.0 的只可读源学机制、禁止依赖或复制**（AGENTS.md §0.6 三条硬线），战斗反射层的核心时序逻辑无论如何都要自研（现成实现都不带本项目的确定性红线与 L0 集成）。

### 第一档：MIT/ISC —— 可直接依赖（走 P1.2.1 同款供应链流程：锁精确版本 + 记录来源/许可/完整性哈希）

| 插件 | 许可 | 功能 | 对应本项目技能 | 采用建议 |
|---|---|---|---|---|
| `mineflayer-pathfinder` | MIT | A* 寻路、复合目标 | `movement.goto`（已接入） | **已锁定 2.4.5**，继续用 |
| `mineflayer-collectblock` | MIT | 寻路+选工具+挖掘+捡拾一体 | `collect.block@1.0.0`（**已接入**） | **已锁定 1.6.0**（SECURITY.md），技能层强制禁自动倒箱、与寻路互斥 |
| `mineflayer-tool` | MIT | 按任务自动选最优工具/武器 | collectblock 依赖（随其加载） | **已锁定 1.2.0**，暂不单独暴露技能 |
| `mineflayer-auto-eat` | MIT | 自动进食（注意：装无前缀版，`@nxg-org` 同名版是 GPL） | L0 安全层进食动作补强 | **可用**，但要与 P1.1 已有的确定性进食逻辑整合而非并存两套 |
| `mineflayer-armor-manager` | MIT | 自动穿戴最优护甲 | `inventory.equip-armor@1.0.0`（**已实现**，自研 TS） | 已作为**首个二档参考技能落地**：机制参考、代码自研；战斗中换甲时序仍自研（§3） |
| `mineflayer-statemachine` | MIT | 行为状态机框架 | 冷启动/角色行为编排的备选框架 | **评估后可用**——若其模型与本项目技能框架冲突则弃用，不强融 |
| `mineflayer-pvp` | MIT | 基础近战 PVP（依赖 pathfinder） | `combat.melee` 的参考底座 | **可用作隔离测试陪练**；正式近战反射按 §5 自研 |
| `minecrafthawkeye` | MIT | 弓箭弹道预测自动瞄准 | `combat.bow`（远程，后补） | 低优先级，需要时直接用 |
| `mineflayer-elytrafly` | ISC | 鞘翅飞行（速度向量式） | `travel.elytra` 的参考 | **谨慎**：无烟花的向量飞行在有反作弊的服易被判定，且 2023 年起停更；M1 鞘翅优先自研烟花推进式 |

### 第二档：GPL-3.0 —— 只读源学机制，禁止 npm 依赖、禁止复制（同 Meteor 待遇）

| 插件 | 功能 | 学什么 |
|---|---|---|
| `@nxg-org/mineflayer-auto-crystal` | 水晶自动放置/引爆 | 放置点评分、break-place 循环节奏、与服务器 tick 对齐——§2 CrystalAura 自研的最直接参考（Mineflayer 语境比 Meteor 的 Java 更贴近） |
| `@nxg-org/mineflayer-custom-pvp` | 剑技（暴击/走位/盾）+ 弓 | 暴击时机判定、CPS 控制、smooth rotation 类人化参数——§5/§7 参考 |
| `@nxg-org/mineflayer-auto-armor` / `auto-eat` / `util-plugin` | 换甲/进食/工具库 | 时序处理细节；换甲机制已被 `inventory.equip-armor@1.0.0` 自研落地（"每槽选最优、平手不换"，代码自研未拷贝 GPL），进食/工具第一档 MIT 版已覆盖 |

> **首个二档技能落地记录**：`inventory.equip-armor@1.0.0` 是第一个"参考 GPL 机制、代码全自研"的技能，非战斗、确定性、可离线单测，作为整条能力接线（skill→capability→mineflayer op）与**日志可判定性**的首个验证目标。水晶/剑技等时序敏感项须在 §0 <50ms 探针通过后再依此路径推进。服务器验证方法见 `docs/skill-verification-runbook.md`。

> **警惕同名坑**：`mineflayer-auto-eat`（MIT）与 `@nxg-org/mineflayer-auto-eat`(GPL) 是两个包。引入依赖时必须核对 npm `license` 字段 + LICENSE 文件，不能只看包名。

### 第三档：无现成、必须自研

- **战斗反射核心时序**（§0~§4 的 <50ms 事件驱动链路、AutoTotem 亚 tick 补位）——GPL 参考实现的架构不带本项目的 L0 集成、确定性红线（自伤评分拒绝、白名单敌我）与审计要求。
- **基岩顶巡逻 + 地狱门扫描**（§8）——本项目独有战术，无现成插件。
- **选址硬规则校验、库存水位线、按角色补货套件**（§9~§12）——业务逻辑，无通用实现。
- **世界记忆服务器隔离**（§13）——本项目数据层设计。

### 引入流程（每个第一档插件一致）

1. `npm view <pkg> license` + 读仓库 LICENSE 文件双重确认许可；
2. 锁精确版本（不用 `^`/`~`），记录来源、许可与完整性哈希（同 `mineflayer-pathfinder` 2.4.5 先例，ROADMAP P1.2.1）；
3. 包一层本项目技能接口（声明输入/输出 Schema、前置条件、能力清单），插件永不直接暴露给 AI 或任务层；
4. L0 暂停/Runtime 停止/外部取消必须能中断插件动作（同 pathfinder 的 `goto-safe` 待遇）；
5. 隔离服过场景测试后才进技能注册表。

1. **时序探针**（§0）——先证明 Mineflayer 无头达得到 <50ms，达不到则停下重估栈。
2. **AutoTotem**（§1）——最高优先级反射，也最能验证事件驱动补位链路。
