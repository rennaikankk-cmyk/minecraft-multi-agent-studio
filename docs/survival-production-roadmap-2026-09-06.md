# 自主生存与基地生产交付边界

日期：2026-09-06。适用路线为 Mineflayer + 确定性 TypeScript + 既有 Rust 寻路模块。P5-D2 已完成，P5-D3 仍按原完成门推进；本文不是 D3 的替代任务。

## 本轮已接线

## 加入基地

参考 `configs/operator-base-assignments.example.json`，这是隔离环境的虚构配置，不会自动启用。

在 Coordinator 启动环境设置 `STUDIO_BASE_ASSIGNMENTS_PATH` 为实际 JSON 文件的绝对路径。生产坐标只放本地受控配置，不提交 Git，不输入模型提示。

- `serverProfileId` 必须匹配目标 Bot 的 ServerProfile，`dimension` 必须使用完整维度名。
- `anchor` 为可达站立点，`bounds` 包含基地受保护结构；每轴跨度最多 512 格。
- `memberBotIds` 是 Studio 的 Bot ID。同一服务器/维度下，每个 Bot 只能有一个当前基地；配置重复指派会整体拒绝，已有注册表保持原状。
- `farms` 的范围必须包含土壤层和作物层。例如土壤 y=64、作物 y=65，则 min.y=64、max.y=65。仅开放胡萝卜、土豆、小麦、甜菜四种基地维护配置。
- 启动时加载并持久化，更新需重启 Coordinator；删除配置条目不会自动拆除基地、撤销旧设施或重置历史。相同农田身份的参数冲突会明确拒绝。
- 配置成员与战斗盟友是两个系统。对方玩家必须由操作者另行加入现有白名单，否则仍按陌生玩家处理。聊天不会自动授予基地成员关系或敌我身份。
- 导入后只确认选址/成员事实，建筑、防怪、补货和产能均需独立实测。

## 最高效率的建设方法

优化指标采用“每 Bot 小时交付到仓库的净可用物资”，同时记录食物消耗、装备损耗、死亡损失、维护时间和服务器负载。建筑格数、瞬时收获或视频宣称的每小时产量不能代替这个指标。

1. **先建立小型可恢复落脚点。** 脱离出生区后封闭外围、门禁、照明、防跌落和逃生通道先完成。房间越大，照明、巡检、清场和暴露面越大。怪物防护与玩家袭击防护分别验证，围墙无法阻止玩家拆墙。
2. **优先食物与库存闭环。** 已有胡萝卜时采用 Bot 维护的水合农田，省去烹饪链；只有小麦时必须补面包合成，土豆应补烘烤。工作路线绕开作物跳跃，保留种子和应急口粮，产出及时入库。一次灌溉 9×9 是 Java 原版常见布局，中央一格水最多覆盖周围 80 格土壤；受版本、光照与插件影响，需要现场验证。
3. **木材和石材按当前瓶颈选择。** 早期天然石材和定点采伐通常比先造复杂机器启动更快。石材用量大且有水/熔岩后，再建隔离流体、可熄火、可观测再生位置的刷石机。树场先做固定地块的种植、自然生长、砍伐和补种；刷木机的树种、空间、骨粉与破坏方案必须分别选型。
4. **存储与村民经济优先于昂贵扩张。** 附近有安全村庄时，保护/运输村民、保留工作站通达、验证交易补货，可为钻石装备提供采矿之外的供应路线。必须考虑村民职业、交易经验、绿宝石来源和不同服务端交易规则。当前仅单次交易技能可用，不等于自动运输和经营交易所已完成。
5. **先做通用掉落物模块，再决定是否专建火药塔。** 骨头可转骨粉，线、火药等可能同时有用；火药确实成为瓶颈后，再专门优化苦力怕设施。刷怪必须考虑玩家距离、怪物上限、加载范围和周边洞穴。Java 原版常见自然刷怪距离条件涉及 24 格内排除与约 128 格范围，但具体刷怪/消失/加载机制、服务端优化配置必须逐一验证，不能把 128 当通用摆放常量。
6. **将高负载和高暴露设施放在独立位置。** 仓库与食物核心保持紧凑，刷怪区域与日常活动区按实测加载和怪物上限安排。多 Bot 扎堆并不线性增加产量；远处 Bot 还可能分摊或占用刷怪预算。传送门、铁路与材料运输可把节省的施工成本重新消耗掉。
7. **通过原型再复制。** 每次只放行一个小模块，验证施工差异、补给、启动、收集、卸载重载、重启、损坏恢复后才复制。让 Bot 保留“配方 + 变体适用条件 + 实测产率 + 失败原因”，才能将经验用于下一处基地。

目前内置 `carrot-farm-9x9` 仅是简化结构示例，`cobble-generator` 也不等于可生产的刷石机。不能因为逐格放完、设施类型已登记或规划图有节点，就宣布自动农场/刷怪塔可用。

## 产能验收与阶段事实

本轮 `FOOD_FACILITY_ACTIVE` 只由跨至少 60 秒的两次正净收获回执暂时支持，缺种、观测失败或不可生产时撤回可用性。该门证明“曾重复收到正产出”，尚未证明稳定食物自给。

下一阶段应以持续运行窗口验收：仓库净入库扣除补种、维护和 Bot 口粮后不亏空；验证自然生长至少两个周期，且服务器重启/区块卸载后能恢复。所有设施统一按以下边界实现：

`材料清单 -> 土地和加载条件核验 -> 固定锚点施工 -> 服务端方块回读 -> 领域调试 -> 库存产出 -> 维护与修复`

刷石机必须观察真实生成和入库；刷怪塔必须统计实际掉落且不堵怪；树场必须保持苗木可持续；交易所必须通过锁定交易和次日补货。这些验收不是通用蓝图验证器可以代劳的。

## Rust 决策

本轮保留已有 `pathfinder-rs`，不新增 Rust 战斗。网络 RTT、服务器 Tick、主线程阻塞、路径计算和协议动作应分别测量。语言迁移不会降低服务器 RTT。

物理 Tick 通常约每 50ms 一次，面板显示其间隔分布；事件循环 P99 是 Node 调度阻塞指标，均不是从危险出现到服务端确认动作的耗时。反射级战斗仍须用专用探针核验。

隔离测试测到秒级事件循环阻塞后，本轮将重要方块扫描改为每类查询后让出事件循环，沿用 Mineflayer 的查询语义，保持完整结果原子发布与作用域失效。这是现有扫描调度修复，单类查询仍同步，不等于 P5-D3 世界观测消费边界全部完成。后续 CPU 密集的几何、路径和候选评分优先放 Worker 或既有 Rust 叶子模块。L0、敌我判断、动作仲裁和控制平面继续保留确定性契约。未经负载测量，不以“战斗应该用 Rust”为理由重写运行时。

## 研究依据与未核验项

本轮最终隔离服验证：两 Bot 各完成 22 种技能，3 项联机测试通过，总时长 58.85 秒。每 Bot 收割 2 格、补种 3 格、锄地 1 格，胡萝卜净增加 6 个。最后 256 个物理间隔样本的 P95 分别为 113.98ms、113.58ms，最大值为 357.23ms、359.18ms，尚不能宣称无卡顿或反射战斗时序达标。该轮结束早于事件循环监控的预热后完整窗口，事件循环 P99 回执为 null，没有填造数值。

- 本地核验：`survival-needs.ts`、`autonomous-director.ts`、`farm-maintenance.ts`、`farm-production.ts`、`base-master-plan.ts`、`combat-driver.ts`、Mineflayer Pathfinder 的部分方块高度处理，以及安装依赖内 Minecraft 1.21.8 协议定义。
- 上游能力入口：[Baritone](https://github.com/cabaletta/baritone)、[Mineflayer API](https://github.com/PrismarineJS/mineflayer/blob/master/docs/api.md)、[Mineflayer Pathfinder](https://github.com/PrismarineJS/mineflayer-pathfinder)。官方 Baritone 版本研究沿用此前交付，本轮没有重新复制 GPL 实现。
- 机制核对入口：[耕地](https://minecraft.wiki/w/Farmland)、[刷怪](https://minecraft.wiki/w/Spawn)、[交易](https://minecraft.wiki/w/Trading)、[树木](https://minecraft.wiki/w/Tree)。本次 Wiki 请求受到站点访问限制，未完成页面实时核验；上面的距离和作物布局是待按实际 Java/服务端版本复核的机制假设，不是本轮新测得的结果。
- 不预设 TNT 复制、零刻、永久区块加载、村民折扣叠加或反作弊兼容。项目需要记录服务器实际配置与经过验证的方案变体。

下一步只推进一个模块：**可投产的食物设施闭环**，补齐供水、照明、防怪、种子隔离、入库、库存供需和自然生长验收，然后再复用其生命周期到其他生产设施。
