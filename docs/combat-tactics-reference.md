# 全角色战术参考清单 · M2/M3 实现输入

> **本文件是"打法/机制描述"，不是代码。** 依据 AGENTS.md §0.6：只描述开源实现（Meteor Client、Baritone、mineflayer-pvp 等）验证过的**机制与参数**，以及本项目自定的作战战术，供在确定性 TypeScript 反射层**自研重写**。**严禁**将任何 GPL 源码逐行翻译或复制进本项目。本文所述均为公开可观察的游戏机制与通用算法思路（idea），不含受版权保护的具体实现。
>
> **覆盖范围**：§0~§8 为战斗反射与侦察战术（战斗类落 **M3 战斗反射**，前提是先实测 Mineflayer 无头达 <50ms 时序，见 §0）；§9~§12 为其余作战角色（突袭/防御/建造与生产/后勤）战术，多数落 **M2/M4**，不依赖战斗时序达标，可并行推进。防御（§10）与建造与生产（§11）刻意针对侦察（§8）的地狱门扫描做**对称反制**。共六类角色（侦察/突袭/防御/战斗/建造与生产/后勤）——建造与生产由建造+农场合并，因食物自动化后不是瓶颈，真正瓶颈是装备/附魔/黑曜石/水晶/附魔瓶等消耗性战备物资。

## 0. 时序预算（决定一切的前提）

| 环节 | 目标 | 说明 |
|---|---|---|
| 事件循环单帧抖动 | < 50ms | 超过则战斗必输；这是 M3 的达标线，也是是否需要 Rust/换栈的唯一判据 |
| 图腾补位（totem re-equip） | 下一 tick（≤50ms） | 图腾被消耗后必须在同帧或下一帧补回副手，否则连击致死 |
| 水晶检测→反应 | ≤1 tick | 看见敌方放水晶到自己反应的窗口 |
| Minecraft 一个 tick | 50ms | 服务器逻辑帧；所有"tick 级"指标都以此为基准 |

**先测量再优化**：M3 第一步不是写战斗逻辑，是写一个能持续采样事件循环延迟的探针，在多 bot、寻路、扫描同时跑的负载下观察 p99 抖动。达标才继续；不达标先定位阻塞源（多半是寻路或区块解析占用主线程）。

## 1. AutoTotem（图腾自动管理）—— 最高优先级反射

**机制**：不死图腾（totem of undying）握在副手（off-hand）时，致命伤会消耗图腾免死。战斗中图腾被消耗后，必须立刻从背包补一个回副手。

**要搬的打法**：
- **触发时机**：监听副手槽变化 / 生命值骤降事件，图腾一旦离开副手 → 下一 tick 立即补位。不要轮询，用事件驱动。
- **优先级**：补图腾的优先级高于**一切**其他动作（攻击、移动、放水晶都要让路）。这是反射层里的最高抢占项。
- **失败降级**：背包无图腾 → 立即触发撤退/断线反射（进入 L0 存活逻辑），不要继续战斗。
- **健康阈值**：可在生命值低于某阈值（如 ≤ 半血）时预防性确认副手有图腾。

**本项目对应**：反射层最高抢占项，技能 `manage.totem`。与 L0 存活逻辑联动。

## 2. CrystalAura（水晶 PvP）—— 核心输出机制

**机制**：末影水晶（end crystal）放在黑曜石/基岩上，被攻击时爆炸，对范围内实体造成大量伤害。攻防两端都靠它。

**要搬的打法（放置点评分）**：
给候选放置位打分，选最优点放置并立即引爆。评分维度：
- **对敌伤害**：候选点爆炸对目标造成的预估伤害（距离越近越高，但受方块遮挡衰减）。
- **对己伤害**：同一次爆炸对自己的预估伤害（必须低于某安全阈值，否则自爆）。
- **可达性**：该点是否有合法承载方块（黑曜石/基岩）、是否被其他方块阻挡放置。
- **净收益** = 对敌伤害 − 对己伤害 × 自保权重。取净收益最高且对己伤害 < 阈值的点。

**引爆时机**：放置后同 tick 或下一 tick 引爆（攻击水晶实体）。延迟越大越容易被敌方先炸。

**自保红线**：任何预估自伤会击穿"当前生命 − 图腾余量"的放置一律否决——宁可不打这一下，也不能自杀。

**本项目对应**：技能 `combat.crystal`。放置点评分是纯几何+伤害公式计算，天然适合确定性代码。**这是最吃时序的模块，M3 的时序测试要以它为主要负载。**

## 3. AutoArmor（护甲自动换装）

**机制**：护甲耐久耗尽会碎；战斗中要把破损护甲换成背包里完好的备件。

**要搬的打法**：
- **耐久阈值**：某件护甲耐久低于阈值（如剩余 < 10% 或绝对值 < N）时，从背包换上同部位完好护甲。
- **换装时机**：避开正在承受连击的瞬间换（换装有短暂空档）；优先在拉开距离/无水晶威胁的间隙换。
- **优先级**：低于 AutoTotem，高于主动进攻。

**本项目对应**：技能 `manage.armor`。

## 4. Surround / 自我保护落块

**机制**：在自己脚下四周（有时含脚下）快速放黑曜石/末地烛，阻止敌方贴脸放水晶、限制敌方近战走位。

**要搬的打法**：
- **落块顺序**：先落四个水平相邻方块（N/E/S/W），封住贴脸水晶位；黑曜石优先（抗爆）。
- **触发**：检测到敌方逼近水晶放置距离时触发；解除战斗后回收/离开。
- **与移动的冲突**：surround 会限制自身移动，需与撤退逻辑协调——撤退优先级更高。

**本项目对应**：可作为 `combat.crystal` 的防御子模式或独立技能。

## 5. KillAura / 近战锁定（谨慎）

**机制**：自动瞄准并攻击范围内目标。

**要搬的打法**：
- **目标选择走确定性敌我识别**（白名单外即敌，见 AGENTS.md §0.1），**不经 AI**。
- **攻击间隔**：遵守武器冷却（attack cooldown），满冷却才挥砍，否则伤害衰减。
- **朝向**：瞄准要"够用即可"，过度精确的瞬间转头是明显 bot 破绽（见 §7 反检测）。

**本项目对应**：技能 `combat.melee`。**注意**：近战 aura 是反作弊最敏感的行为之一，优先级低于水晶战术，且要配合反检测节流。

## 6. 寻路与移动（Baritone 打法参考）

**机制**：Baritone 是业界最强的 Minecraft 寻路实现（A* + 大量实战启发）。

**要搬的打法（思路，不搬代码）**：
- **公路循迹**：无规则服的坐标轴高速/地狱顶层公路是笔直隧道，循迹可用简单的"沿轴对齐 + 前方障碍检测"，不需要完整 A*。
- **鞘翅飞行力学**：起飞、烟花助推节奏、落地缓冲——纯物理，确定性实现。
- **基岩顶巡逻**（本项目侦察角色核心）：能上基岩顶时移动最省事（平坦无阻挡）。见 §8。

**边界**：远距离探索寻路是 CPU 密集，若实测阻塞事件循环（>50ms），才考虑抽独立 Rust 寻路服务（AGENTS.md §0.5）。**先测量。**

## 7. 反检测 / 类人化（诚实边界）

**目标**：降低明显的 bot 破绽，**不等于免疫封号**（AGENTS.md §0.4）。

**要搬的打法**：
- 转头/瞄准加入微小噪声与转速上限，避免瞬间 180°。
- 动作之间加入人类量级的随机延迟抖动，避免固定周期。
- 避免亚 tick 完美连招（完美到不可能是人的操作 = 明显信号）。

**红线**：这些只降低破绽，残余封号风险由使用者承担；不得在文档/代码里把"反封号"写成已解决。

## 8. 基岩顶巡逻 + 地狱门扫描（本项目侦察角色专属战术）

> 这是用户提出、本项目侦察角色的核心侦察手段，不是通用外挂功能。

**原理**：
1. **基岩顶可达性**：部分无规则服未修补下界基岩顶（Y=127 之上）通道，bot 可上到基岩顶。顶上平坦、无怪物、鞘翅移动效率全游戏最高。
2. **区块数据可扫描**：服务器向客户端同步的区块数据包含**脚下整个区块柱**的方块信息。bot 站在基岩顶即可读取顶层以下的方块，**无需下到下界内部**即可扫描已加载区块中的地狱门方块。
3. **已激活门 = 基地嫌疑**：已激活的地狱门（含紫色传送门方块）意味着有人使用过。**下界坐标 ×8 = 主世界对应坐标**，是主世界基地的高概率嫌疑点。

**打法流程**：
- **入服先探测**：尝试上基岩顶。成功 → 启用本战术；失败（服务器已修补）→ **自动去除此项**，退回地狱顶层公路巡逻，不做无谓尝试。探测结果记入 **ServerProfile**，换服重新探测。
- **巡逻扫描**：在基岩顶沿网格/螺旋巡逻，对每个新加载区块扫描地狱门方块（传送门方块 nether_portal / 黑曜石框架）。
- **标记而非核实**：扫描 bot **只负责标记**——把门的下界坐标、激活状态、发现时间**写入共享世界记忆**（pgvector，P2.1）。
- **分工核实**：由**战略层**读取标记，按优先级（活跃度、聚集度）指派**其他侦察 bot** 前往主世界对应坐标（×8）核实是否有基地。上层标记、下层核实，是集群协作的典型样例。

**确定性 vs AI 切分**：
- 确定性：基岩顶可达性探测、区块地狱门扫描、坐标 ×8 换算、标记写入。
- AI（战略层）：已标记门的核实优先级排序、是否值得投入 bot 核实。

**本项目对应**：技能 `probe.roof`（可达性探测）、`scan.portal`（区块地狱门扫描）、`log.coordinate`（标记写入）。

## 9. 突袭 Raider —— 攻破基地

**目标**：以最低资源代价打穿基地外壳、翻走高价值物资、全身而退。

**要搬的打法**：
- **破墙优先级**：黑曜石抗爆极高，硬用 TNT 费料——首选**末影水晶贴墙连爆**（对方块破坏效率高于 TNT），附魔镐补挖，凋灵拆大面积墙。评估目标外壳材质后选最省料的方式。
- **接近路线**：不走正门。从远处斜向下挖，或经**下界对应点（×8）**贴近再上主世界，减少被防御 bot 边界扫描发现。
- **择时**：优先在目标**无人在线 / 防御 bot 撤离**时突入（侦察角色提供的玩家活动规律是关键输入）。
- **翻箱优先级**：潜影盒 > 末影箱线索 > 附魔台/信标等高价值方块 > 普通资源。背包满优先打包潜影盒带走。
- **脱离**：预置**珍珠停滞**（ender pearl stasis）或竖井下潜逃生路线；达撤退阈值（生命、来敌数）立即断线保号。**突袭 bot 死亡 = 损失一整套突入装备，撤离优先于贪财。**

**确定性 vs AI**：确定性=敌我识别、破墙机制、翻箱优先级、撤退触发；AI=突入方式选择、何时放弃。

**本项目对应**：`mine.obsidian` · `place.crystal` · `ignite.tnt` · `spawn.wither` · `loot.chest` · `breach.wall`。依赖侦察坐标、农场原料、战斗护航。

## 10. 防御 Defender —— 守基地（对称反侦察）

**核心认知**：敌人会用**我们侦察角色同一套手段**（基岩顶地狱门扫描、公路跟踪）找我们，所以防御从"不被发现"开始。

**要搬的打法**：
- **反坐标暴露**：己方基地**不用主世界地狱门**，或用完即拆/远置，避免暴露 ×8 坐标（这正是 §8 扫描战术的反制）。核心仓与门厅分离。
- **分层预警**：外环（区块加载边缘检测新实体）→ 中环（边界巡逻发现玩家）→ 内环（触墙/破坏方块）逐级升级报警。
- **迟滞而非死守**：单个防御 bot 打不过突袭队，价值在**拖延 + 报警 + 疏散**——封门（黑曜石/岩浆幕）、水阻爬墙，拖到战斗 bot 回援或核心物资撤离完成。
- **反跟踪**：发现被玩家尾随时不直接回基地，绕路/断线甩开，**绝不把敌人带回家**。
- **失陷协议**：达失陷阈值触发 `COMPROMISED`——核心物资撤离、≥10000 格外重建，撤离优先于反击。

**确定性 vs AI**：确定性=敌我识别、入侵探测、报警派发、巡逻路径、反跟踪甩尾；AI=迎战/躲藏/撤离、是否触发失陷协议。

**本项目对应**：`patrol.perimeter` · `detect.intruder` · `alert.swarm` · `seal.entrance`。

## 11. 建造与生产 Infrastructure —— 隐蔽 + 战争经济引擎

**为什么合并（建造 + 农场）**：自动化农场是**建造的产物**，建好即自运转，不是需要持续操作的独立角色。而且**食物不是瓶颈**——金萝卜/金苹果农场一旦建成产量绝对够吃，fire-and-forget。真正需要盯产量的是**消耗性战备物资**：装备、附魔、黑曜石、末影水晶、附魔瓶（经验瓶）。本角色 = 建隐蔽基地 + 搭建并运转这些战备物资生产线。

**核心认知**：无规则服第一防御是**没人找得到**（第二才是墙厚）；没有稳定的战备物资生产，突袭和战斗就是无源之水。

**要搬的打法（建造/隐蔽）**：
- **选址硬规则（确定性可校验）**：远离坐标轴与主干道 N 格以上、远离主世界地狱门连线、**避开整数/对称/整千坐标**（人类爱建在整千坐标，避开反而隐蔽）。可编码的布尔校验，不靠 AI 直觉。
- **伪装与埋深**：外壳埋地下/山体，入口伪装（假墙、无关方块群）。
- **抗爆结构**：核心库用**黑曜石壳 + 隔空层**抵御水晶连爆；关键箱藏多层无关空间、不集中堆放（一次被翻不全损）。
- **分散建点**：生产/仓储/休整分点建、坐标各自独立，高特征建筑（刷怪塔）远离核心；任一点暴露不牵连其他。
- **己方标记**：所有隐蔽点坐标写入共享世界记忆并标"己方隐蔽点"，**防止己方侦察 bot 把自家门误标为嫌疑基地**。

**要搬的打法（生产/经济）**：
- **按战争节奏调产**：要突袭 → 火药/水晶原料/末影珍珠/TNT 拉满；防御期 → 图腾材料/黑曜石/附魔瓶优先。
- **库存水位线**：每种战备物资设**低/目标/上限**三档。低于低水位报警并顶格生产，到上限转产其他，避免单一囤积。确定性计数逻辑。
- **食物免管理**：食物线建好即忽略，不设水位、不占调度注意力。
- **抗突袭**：生产点与核心仓**分离且不放全部产出**——成品定期由后勤转运隐蔽仓，现场只留在制品；即使某生产点被端，战争储备不清零。

**确定性 vs AI**：确定性=选址硬规则校验、方块摆放/蓝图执行、农场循环、收割补种、库存水位计数与报警；AI=选址/布局/建什么、战备物资优先级与水位阈值。

**本项目对应**：`build.blueprint` · `place.blocks` · `build.wall` · `build.hidden-base` · `farm.crop` · `farm.mob` · `generate.obsidian` · `smelt` · `craft.item` · `enchant.gear`。

## 12. 后勤 Logistics —— 让损失可补充

**核心认知**：作战集群"死一个 bot 掉一套装"是常态，后勤把损失变成可快速补充，把前线和仓储解耦。

**要搬的打法**：
- **预置补货套件**：按角色打包标准潜影盒（突袭套=镐/水晶/TNT/珍珠/图腾；战斗套=甲/水晶/图腾/金苹果；侦察套=鞘翅/烟花/食物）。bot 死后重生领套即可再上线，无需临时凑装。
- **隐蔽转运**：运输是暴露风险最高的环节（满箱 bot 是活靶）——路线避开公路热点、分批小额运、必要时经下界短途；贵重整合进潜影盒减少往返。
- **分散储备（3-2-1 思路）**：核心隐蔽仓 + 前线周转仓 + 应急暗仓，任一仓被端不全损。每仓库存与坐标写入共享世界记忆（仅集群可读）。
- **前线解耦**：前线 bot 只管打，补给由后勤推送到就近周转仓，前线不回后方，降低暴露主基地风险。

**确定性 vs AI**：确定性=打包/分类/补货/转运执行；AI=补货优先级、转运时机与路线取舍。

**本项目对应**：`store.stash` · `pack.shulker` · `resupply` · `sort.items`。

## 落地顺序建议（M3 内部）

1. **时序探针**（§0）——先证明 Mineflayer 无头达得到 <50ms，达不到则停下重估栈。
2. **AutoTotem**（§1）——最高优先级反射，也最能验证事件驱动补位链路。
3. **CrystalAura 放置点评分 + 自保红线**（§2）——核心输出，主要时序负载。
4. **AutoArmor / Surround**（§3/§4）——补齐攻防。
5. **近战 aura + 反检测节流**（§5/§7）——最后，最敏感。

侦察角色的**基岩顶巡逻 + 地狱门扫描**（§8）属 M2（非战斗生产角色），可与 M3 并行推进，不依赖战斗时序达标。
