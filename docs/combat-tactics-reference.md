> **本文件是"打法/机制描述"，不是代码。** 依据 AGENTS.md §0.6：只描述开源实现（Meteor Client、Baritone、mineflayer-pvp 等）验证过的**机制与参数**，供本项目在确定性 TypeScript 反射层**自研重写**。**严禁**将任何 GPL 源码逐行翻译或复制进本项目。本文所述均为公开可观察的游戏机制与通用算法思路（idea），不含受版权保护的具体实现。
>

## 0. 时序预算（决定一切的前提）

| 环节 | 目标 | 说明 |
|---|---|---|
| 事件循环单帧抖动 | < 50ms | 超过则战斗必输；这是 M3 的达标线，也是是否需要 Rust/换栈的唯一判据 |
| 图腾补位（totem re-equip） | 下一 tick（≤50ms） | 图腾被消耗后必须在同帧或下一帧补回副手，否则连击致死 |
| 水晶检测→反应 | ≤1 tick | 看见敌方放水晶到自己反应的窗口 |
| Minecraft 一个 tick | 50ms | 服务器逻辑帧；所有"tick 级"指标都以此为基准 |

**先测量再优化**：M3 第一步不是写战斗逻辑，是写一个能持续采样事件循环延迟的探针，在多 bot、寻路、扫描同时跑的负载下观察 p99 抖动。达标才继续；不达标先定位阻塞源（多半是寻路或区块解析占用主线程）。

## 1. AutoTotem（图腾自动管理）—— 最高优先级反射

**机制**：不死图腾（totem of undying）握在副手（off-hand）时，致命伤会消耗图腾免死。战斗中图腾被消耗后，必须立刻从背包补一个回副手。

**要搬的打法**：
- **触发时机**：监听副手槽变化 / 生命值骤降事件，图腾一旦离开副手 → 下一 tick 立即补位。不要轮询，用事件驱动。
- **优先级**：补图腾的优先级高于**一切**其他动作（攻击、移动、放水晶都要让路）。这是反射层里的最高抢占项。
- **失败降级**：背包无图腾 → 立即触发撤退/断线反射（进入 L0 存活逻辑），不要继续战斗。
- **健康阈值**：可在生命值低于某阈值（如 ≤ 半血）时预防性确认副手有图腾。

**本项目对应**：反射层最高抢占项，技能 `manage.totem`。与 L0 存活逻辑联动。

## 2. CrystalAura（水晶 PvP）—— 核心输出机制

**机制**：末影水晶（end crystal）放在黑曜石/基岩上，被攻击时爆炸，对范围内实体造成大量伤害。攻防两端都靠它。

**要搬的打法（放置点评分）**：
给候选放置位打分，选最优点放置并立即引爆。评分维度：
- **对敌伤害**：候选点爆炸对目标造成的预估伤害（距离越近越高，但受方块遮挡衰减）。
- **对己伤害**：同一次爆炸对自己的预估伤害（必须低于某安全阈值，否则自爆）。
- **可达性**：该点是否有合法承载方块（黑曜石/基岩）、是否被其他方块阻挡放置。
- **净收益** = 对敌伤害 − 对己伤害 × 自保权重。取净收益最高且对己伤害 < 阈值的点。

**引爆时机**：放置后同 tick 或下一 tick 引爆（攻击水晶实体）。延迟越大越容易被敌方先炸。

**自保红线**：任何预估自伤会击穿"当前生命 − 图腾余量"的放置一律否决——宁可不打这一下，也不能自杀。

**本项目对应**：技能 `combat.crystal`。放置点评分是纯几何+伤害公式计算，天然适合确定性代码。**这是最吃时序的模块，M3 的时序测试要以它为主要负载。**

## 3. AutoArmor（护甲自动换装）

**机制**：护甲耐久耗尽会碎；战斗中要把破损护甲换成背包里完好的备件。

**要搬的打法**：
- **耐久阈值**：某件护甲耐久低于阈值（如剩余 < 10% 或绝对值 < N）时，从背包换上同部位完好护甲。
- **换装时机**：避开正在承受连击的瞬间换（换装有短暂空档）；优先在拉开距离/无水晶威胁的间隙换。
- **优先级**：低于 AutoTotem，高于主动进攻。

**本项目对应**：技能 `manage.armor`。

---

## 4. Surround / 自我保护落块

**机制**：在自己脚下四周（有时含脚下）快速放黑曜石/末地烛，阻止敌方贴脸放水晶、限制敌方近战走位。

**要搬的打法**：
- **落块顺序**：先落四个水平相邻方块（N/E/S/W），封住贴脸水晶位；黑曜石优先（抗爆）。
- **触发**：检测到敌方逼近水晶放置距离时触发；解除战斗后回收/离开。
- **与移动的冲突**：surround 会限制自身移动，需与撤退逻辑协调——撤退优先级更高。

**本项目对应**：可作为 `combat.crystal` 的防御子模式或独立技能。

---

## 5. KillAura / 近战锁定（谨慎）

**机制**：自动瞄准并攻击范围内目标。

**要搬的打法**：
- **目标选择走确定性敌我识别**（白名单外即敌，见 AGENTS.md §0.1），**不经 AI**。
- **攻击间隔**：遵守武器冷却（attack cooldown），满冷却才挥砍，否则伤害衰减。
- **朝向**：瞄准要"够用即可"，过度精确的瞬间转头是明显 bot 破绽（见 §7 反检测）。

**本项目对应**：技能 `combat.melee`。**注意**：近战 aura 是反作弊最敏感的行为之一，优先级低于水晶战术，且要配合反检测节流。

## 6. 寻路与移动（Baritone 打法参考）

**机制**：Baritone 是业界最强的 Minecraft 寻路实现（A* + 大量实战启发）。

**要搬的打法（思路，不搬代码）**：
- **公路循迹**：无规则服的坐标轴高速/地狱顶层公路是笔直隧道，循迹可用简单的"沿轴对齐 + 前方障碍检测"，不需要完整 A*。
- **鞘翅飞行力学**：起飞、烟花助推节奏、落地缓冲——纯物理，确定性实现。
- **基岩顶巡逻**（本项目侦察角色核心）：能上基岩顶时移动最省事（平坦无阻挡）。见 §8。

**边界**：远距离探索寻路是 CPU 密集，若实测阻塞事件循环（>50ms），才考虑抽独立 Rust 寻路服务（AGENTS.md §0.5）。**先测量。**

## 7. 反检测 / 类人化（诚实边界）

**目标**：降低明显的 bot 破绽，**不等于免疫封号**（AGENTS.md §0.4）。

**要搬的打法**：
- 转头/瞄准加入微小噪声与转速上限，避免瞬间 180°。
- 动作之间加入人类量级的随机延迟抖动，避免固定周期。
- 避免亚 tick 完美连招（完美到不可能是人的操作 = 明显信号）。

**红线**：这些只降低破绽，残余封号风险由使用者承担；不得在文档/代码里把"反封号"写成已解决。

## 8. 基岩顶巡逻 + 地狱门扫描（本项目侦察角色专属战术）

> 这是用户提出、本项目侦察角色的核心侦察手段，不是通用外挂功能。

**原理**：
1. **基岩顶可达性**：部分无规则服未修补下界基岩顶（Y=127 之上）通道，bot 可上到基岩顶。顶上平坦、无怪物、鞘翅移动效率全游戏最高。
2. **区块数据可扫描**：服务器向客户端同步的区块数据包含**脚下整个区块柱**的方块信息。bot 站在基岩顶即可读取顶层以下的方块，**无需下到下界内部**即可扫描已加载区块中的地狱门方块。
3. **已激活门 = 基地嫌疑**：已激活的地狱门（含紫色传送门方块）意味着有人使用过。**下界坐标 ×8 = 主世界对应坐标**，是主世界基地的高概率嫌疑点。

**打法流程**：
- **入服先探测**：尝试上基岩顶。成功 → 启用本战术；失败（服务器已修补）→ **自动去除此项**，退回地狱顶层公路巡逻，不做无谓尝试。探测结果记入 **ServerProfile**，换服重新探测。
- **巡逻扫描**：在基岩顶沿网格/螺旋巡逻，对每个新加载区块扫描地狱门方块（传送门方块 nether_portal / 黑曜石框架）。
- **标记而非核实**：扫描 bot **只负责标记**——把门的下界坐标、激活状态、发现时间**写入共享世界记忆**（pgvector，P2.1）。
- **分工核实**：由**战略层**读取标记，按优先级（活跃度、聚集度）指派**其他侦察 bot** 前往主世界对应坐标（×8）核实是否有基地。上层标记、下层核实，是集群协作的典型样例。

**确定性 vs AI 切分**：
- 确定性：基岩顶可达性探测、区块地狱门扫描、坐标 ×8 换算、标记写入。
- AI（战略层）：已标记门的核实优先级排序、是否值得投入 bot 核实。

**本项目对应**：技能 `probe.roof`（可达性探测）、`scan.portal`（区块地狱门扫描）、`log.coordinate`（标记写入）。

## 落地顺序建议（M3 内部）

1. **时序探针**（§0）——先证明 Mineflayer 无头达得到 <50ms，达不到则停下重估栈。
2. **AutoTotem**（§1）——最高优先级反射，也最能验证事件驱动补位链路。
3. **CrystalAura 放置点评分 + 自保红线**（§2）——核心输出，主要时序负载。
4. **AutoArmor / Surround**（§3/§4）——补齐攻防。
5. **近战 aura + 反检测节流**（§5/§7）——最后，最敏感。

侦察角色的**基岩顶巡逻 + 地狱门扫描**（§8）属 M2（非战斗生产角色），可与 M3 并行推进，不依赖战斗时序达标。
